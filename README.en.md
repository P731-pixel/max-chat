# MAX Chat — React Chat with GREEN-API Integration

**MAX Chat** is a testing project that implements a web-based chat interface using React and TypeScript, with GREEN-API integration for sending and receiving messages.

[Русская версия](README.md)

## Features

- **Two operating modes:** DEMO for testing the interface and REAL for interacting with GREEN-API.
- **GREEN-API connection:** configure the API URL, `idInstance`, and `apiTokenInstance`.
- **Chat management:** create chats using phone numbers and switch between conversations.
- **Messaging:** send and display messages in the active chat history.
- **Incoming messages:** poll GREEN-API notifications in REAL mode.
- **Error handling:** display sending errors and retry failed messages.
- **Chat interface:** conversation list, message history, and API connection settings.

## Operating Modes

### DEMO

The demo mode lets you test the interface without connecting to a real GREEN-API instance.

You can create chats, send test messages, and receive simulated replies. Demo replies are generated by the application and are not messages from a real contact.

### REAL

The real mode uses GREEN-API to send messages and receive incoming notifications.

Provide your GREEN-API instance credentials:

- **API URL** — the API endpoint.
- **Instance ID** — the instance identifier.
- **API Token** — the access token.

REAL mode depends on API availability, instance status, and valid configuration.

## Current Limitations

- Chat history is stored in memory and is lost when the page is reloaded.
- Replies in DEMO mode are simulated.
- The main messaging workflow focuses on text messages.
- REAL mode requires an available and properly configured GREEN-API instance.
- The project is primarily intended for learning and demonstration.

## Security Considerations

The current architecture communicates with GREEN-API directly from the browser. Consequently, the instance identifier and API token may be accessible through browser developer tools and network requests.

**Do not deploy this architecture unchanged as a public production application.**

For production use, move GREEN-API communication to a backend, store secrets in environment variables or a secure secret store, and implement server-side authentication, input validation, and access control.

Never commit real API tokens or other secrets to GitHub.
